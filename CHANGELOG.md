# История изменений

Все заметные изменения проекта фиксируются здесь. Даты указаны в формате YYYY-MM-DD.

## [Unreleased]

### Added
- Начат runtime-каркас модуля: публичные DTO/enum API, EventHandle, no-op и рабочий handle, EventService, контракт EventStorage, генератор UUID v4, Sanitizer и регистрация классов через Bitrix Loader.
- Добавлены unit-тесты EventService: проверка маскирования метаданных, выключенного по умолчанию payload, успешной и повторной финализации, маскирования токена в сообщении исключения.
- Исправлено маскирование Authorization Bearer и объявление Throwable в NullEventHandle.
- Добавлены Composer/PHPUnit dev-конфигурация, первые unit-тесты для входных данных, UUID, NullEventHandle и Sanitizer, а также GitHub Actions workflow для PHP 8.2–8.4. Тесты пока не запускались.


### Added
- Добавлен [TRANSACTION-SPIKE.md](docs/TRANSACTION-SPIKE.md) с пошаговым протоколом проверки rollback, именованного соединения, отказов, блокировок, CLI и ORM; на тестовой VM выполнены ограниченные сценарии A/B и проверка отказа соединения C на уровне тестового harness.
- Создана начальная документация концепции CodeMatrix Integration Inspector.
- Зафиксированы предварительные границы MVP.
- Добавлены архитектурное предложение, дорожная карта и журнал решений.
- Добавлен проект публичного API: фасад, EventHandle, жизненный цикл, корреляция, payload и политика отказов.
- Добавлен документ первичной проверки требований совместимости платформы.
- Добавлен корневой файл LICENSE со стандартным текстом MIT License.
- Добавлена ревизия публичного API с рекомендациями по no-op handle, источникам, идентификаторам, финализации и payload.
- API.md обновлён до версии 0.2: begin() всегда возвращает безопасный handle, справочник источников отделён от события, уточнены идентификаторы, финализация и правила payload.
- Добавлен проект физической модели хранения: таблицы событий, данных и источников, индексы, лимиты, retention и сценарии проверки ORM/транзакций.
- Примеры в MVP и журнале решений синхронизированы с API v0.2; уточнены входной payload, контекст и ограничения идентификаторов.
- Добавлен TEST-PLAN.md с проверяемыми сценариями API, безопасности, хранилища, очистки, установки и критериями допуска к альфе. Тесты ещё не реализованы и не запускались.
- Добавлены TRANSACTION-STRATEGY.md и INSTALLATION.md: описаны режимы соединения, ограничения при rollback, опциональная независимая запись, безопасное обновление и сохранение данных при обычном удалении.
- В DECISIONS.md добавлено D-013; в TEST-PLAN.md добавлены проверки default/named connection и rollback. Экспериментально подтверждены сценарии A/B для двух отдельных именованных соединений к одной тестовой БД; отказ соединения проверен только в тестовом harness, без реализации Inspector/Storage.
- API-REVIEW.md синхронизирован с API v0.2: уточнён формат parentEventId и добавлены ссылки на транзакционную стратегию и установщик.
- Добавлен DEV-ENVIRONMENT.md: зафиксирована изоляция dev-зависимостей, PHPUnit 11.5 для PHP 8.2 и разделение unit/integration/security/compatibility тестов. Composer-конфигурация ещё не добавлена.
- Добавлен IMPLEMENTATION-PLAN.md: описаны структура каталога модуля, границы компонентов, направление зависимостей и безопасная последовательность реализации.

### Changed
- Уточнена спецификация MVP с учётом контракта API.
- Архитектура дополнена разделом публичного API и ссылкой на совместимость.
- D-006 уточнено по официальным требованиям PHP 8.2 и MySQL 8.0; совместимость самого модуля не объявлена подтверждённой.
- Стратегия продукта закреплена: бесплатное распространение без платных редакций и подписок; основной эффект — польза сообществу и узнаваемость CodeMatrix STUDIO.
- README и PRODUCT.md отражают репутационную и общественную цель проекта.
- Выбрана MIT License (SPDX: MIT); README и PRODUCT.md содержат условия и ссылку на LICENSE.
- В ROADMAP добавлен предварительный календарный план на 8–10 недель с указанием допущений и контрольных результатов.
- В ROADMAP добавлен отдельный этап ревизии API; рекомендации пока не считаются утверждённым публичным контрактом.

### Notes
- Runtime-каркас реализован частично; SQL-хранилище, установщик, фасад Inspector и административный интерфейс ещё не реализованы.
- Документы API и архитектуры являются проектными предложениями и требуют согласования.
- Первичная проверка платформенных требований не заменяет тестирование модуля на конкретных версиях ядра и СУБД.
- Официальные материалы по установке модулей и ORM учтены в API-REVIEW.md; фактическая совместимость должна быть проверена на целевых окружениях.
- MIT разрешает коммерческое использование и распространение производных работ при сохранении уведомления об авторских правах и текста лицензии.
- Календарные оценки не являются гарантированной датой выпуска и пересматриваются по фактическому прогрессу.
