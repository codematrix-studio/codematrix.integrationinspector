# Журнал проектных решений

Здесь фиксируются решения, их статус, причина и последствия. Черновые предложения не считаются утверждёнными решениями.

## D-001. Самостоятельный продукт, не основанный на kit.importxml

- **Дата:** 2026-11-24
- **Статус:** принято
- **Решение:** CodeMatrix Integration Inspector разрабатывается как отдельный продукт с нуля. Репозиторий и код `kit.importxml` / `codematrix.importxml` не используются как исходная база.
- **Причина:** продукт должен иметь самостоятельную архитектуру и кодовую базу.

## D-002. Диагностика, а не конструктор интеграций

- **Дата:** 2026-11-24
- **Статус:** принято
- **Решение:** модуль регистрирует и анализирует события интеграций; он не реализует сами подключения к внешним системам.
- **Причина:** универсальный диагностический слой применим к разным проектам и не разрастается в набор несвязанных коннекторов.

## D-003. Явное подключение через API/адаптеры

- **Дата:** 2026-11-24
- **Статус:** принято как принцип
- **Решение:** интеграции подключаются явно через публичный API или адаптеры. Не обещать автоматический перехват всех запросов.
- **Причина:** предсказуемость, контроль данных и отсутствие скрытого вмешательства в чужой код.

## D-004. Повтор запросов не входит в MVP

- **Дата:** 2026-11-24
- **Статус:** принято
- **Решение:** в первой версии нет функции повторного выполнения операций.
- **Причина:** повтор может создать дубли заказов, платежей и иных побочных эффектов.

## D-005. Безопасность данных обязательна

- **Дата:** 2026-11-24
- **Статус:** принято
- **Решение:** секреты маскируются до записи; тела не сохраняются по умолчанию; предусматриваются ограничения размера и контроль доступа.
- **Причина:** журнал интеграций потенциально содержит токены, персональные и коммерческие данные.

## D-006. Минимальная версия PHP

- **Дата:** 2026-11-24
- **Статус:** подтверждено для текущих требований платформы; матрица модуля не утверждена
- **Решение:** целевая нижняя граница PHP — 8.2, поскольку официальная документация 1С-Битрикс указывает PHP 8.2.0 с 1 февраля 2026 года. Минимум MySQL платформы — 8.0.
- **Причина:** опора на актуальные официальные требования платформы.
- **Ограничение:** это не подтверждает совместимость самого модуля со всеми версиями ядра, MariaDB или PostgreSQL. См. [COMPATIBILITY.md](COMPATIBILITY.md).

## D-007. Бесплатное распространение и отсутствие коммерческих редакций

- **Дата:** 2026-11-24
- **Статус:** принято
- **Решение:** CodeMatrix Integration Inspector распространяется бесплатно. Платные редакции, подписки и модель Free/Pro/Business не являются целью проекта.
- **Причина:** главная стратегическая задача продукта — практическая польза сообществу 1С-Битрикс-разработчиков, узнаваемость CodeMatrix STUDIO и публичное подтверждение инженерной экспертизы.
- **Ограничение:** конкретная лицензия исходного кода ещё не выбрана. Бесплатность не равна автоматически разрешению на изменение и повторное распространение; права будут закреплены отдельным решением и файлом LICENSE.

## D-008. Репозиторий — источник истины по проекту

- **Дата:** 2026-11-24
- **Статус:** принято
- **Решение:** требования, архитектура, решения, изменения и статус разработки фиксируются в этом репозитории. Важные решения из обсуждений переносятся в документацию до начала реализации.
- **Причина:** сохранять историю проекта независимо от отдельных диалогов.

## D-009. Публичный API и жизненный цикл событий

- **Дата:** 2026-11-24
- **Статус:** проект; требуется согласование
- **Решение:** предложен фасад `Inspector::begin()`, объект `EventHandle` с методами финализации `succeed()` и `fail()`, состояния `pending` / `success` / `error`, явные correlation/parent IDs и best-effort политика по умолчанию.
- **Причина:** отделить бизнес-операцию от диагностики, сделать контракт транспорта-независимым и предотвратить влияние отказа логгера на основную интеграцию.
- **Последствия:** API не управляет транзакциями приложения; не поддерживает передачу handle между процессами; повторная финализация не меняет результат.
- **Документ:** [API.md](API.md).

## D-010. Тела запросов и ответов выключены по умолчанию

- **Дата:** 2026-11-24
- **Статус:** принято как принцип безопасности MVP
- **Решение:** тела не сохраняются без явной настройки и передачи вызывающим кодом; санитарная обработка выполняется до постоянной записи.
- **Причина:** снизить риск утечки секретов и персональных/коммерческих данных.

## D-011. Репутационная и общественная цель продукта

- **Дата:** 2026-11-24
- **Статус:** принято
- **Решение:** проект рассматривается как бесплатный публичный инженерный продукт CodeMatrix STUDIO, а не как самостоятельный источник выручки. Приоритет — качество, полезность, открытая демонстрация экспертизы и узнаваемость бренда среди разработчиков 1С-Битрикс.
- **Причина:** продукт должен помогать сообществу и одновременно служить доказательством практического опыта для профессионального позиционирования и поиска работы/проектов.
