# Архитектура (предварительная)

- **Версия:** 0.1
- **Дата:** 2026-11-24
- **Статус:** проектное предложение, подлежит технической проверке.

## 1. Общая схема

Интеграция приложения
→ публичный API Inspector
→ нормализация события
→ санитарная обработка данных (Sanitizer)
→ Storage
→ административный интерфейс.

Диагностическая подсистема не должна владеть бизнес-логикой интеграции.

## 2. Предлагаемые подсистемы

| Подсистема | Ответственность |
|---|---|
| API / Facade | Стабильная точка входа для интеграций |
| Event | Модель и жизненный цикл события |
| Source | Регистрация источников интеграций |
| Sanitizer | Маскирование и ограничение данных |
| Storage | Сохранение и чтение событий |
| Filter | Фильтрация и поиск |
| Cleanup | Удаление устаревших данных |
| Admin | Интерфейс управления и просмотра |

## 4. Пространство имён

Предварительно: `CodeMatrix\\IntegrationInspector`.

Публичные классы API должны быть минимальны и стабильны. Внутренние классы хранения и реализации не следует объявлять частью публичного контракта.

## 5. Хранилище

Предварительная логическая модель:

- `b_cmi_source` — источники интеграций;
- `b_cmi_event` — метаданные событий;
- `b_cmi_event_data` — дополнительные данные запроса/ответа.

Окончательная схема зависит от оценки объёмов, ограничений БД, требований к поиску и возможностей ORM Битрикс. Не фиксировать имена/типы колонок до отдельного проектирования схемы.

## 6. Надёжность

Нужно определить и протестировать:
- безопасный режим при ошибке записи;
- поведение при переполнении лимита;
- обработку больших payload;
- защиту от рекурсивного логирования;
- транзакционные границы;
- очистку и конкурентную запись.

## 7. Совместимость

Предварительная цель PHP 8.2+. Точная версия ядра Битрикс, редакции продукта и версии MySQL/MariaDB должны быть определены после проверки официальной матрицы поддержки и тестовой среды.
