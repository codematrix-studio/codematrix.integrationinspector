# Совместимость и технические ограничения

- **Дата проверки:** 2026-11-24
- **Статус:** результаты первичной проверки официальных материалов; матрица самого модуля ещё не утверждена.

## 1. Требования платформы 1С-Битрикс

Официальные материалы 1С-Битрикс указывают:
- PHP не ниже 8.2.0 с 1 февраля 2026 года;
- MySQL не ниже 8.0;
- PostgreSQL доступен для соответствующих редакций уровня Энтерпрайз;
- для актуальной платформы рекомендуется использовать поддерживаемую стабильную версию PHP.

Источники:
- [Технические требования «1С-Битрикс: Управление сайтом»](https://www.1c-bitrix.ru/products/cms/requirements.php)
- [Документация разработчика: реализация и системные требования](https://dev.1c-bitrix.ru/user_help/reqintro.php?print=Y)
- [Учебный курс: требования к серверному программному обеспечению](https://dev.1c-bitrix.ru/learning/course/?COURSE_ID=32&LESSON_ID=2593)

## 2. Предварительная цель модуля

- PHP: 8.2+ — согласуется с текущим минимальным требованием платформы, но не является окончательной матрицей совместимости модуля.
- База данных: MySQL 8.0+ — минимальное требование платформы.
- MariaDB: не заявлять поддержку только на основании совместимости с MySQL. Нужны отдельные тесты на конкретных версиях MariaDB и проверка используемых SQL/ORM возможностей.
- PostgreSQL: не заявлять поддержку в MVP, пока не определены целевые редакции Битрикс, API доступа к данным и отдельная тестовая матрица.

## 3. Что ещё требуется проверить

1. Минимальная версия ядра Битрикс и поддерживаемые обновления.
2. Установщик/деинсталлятор модуля и схема регистрации административных страниц.
3. ORM/API Битрикс: типы полей, индексы, JSON/длинные тексты, миграции схемы и фактическая работа DataManager с именованным соединением.
4. ConnectionPool и отдельное именованное соединение: независимость транзакционной сессии, права доступа и CLI/cron. См. [TRANSACTION-STRATEGY.md](TRANSACTION-STRATEGY.md).
5. Работа с MySQL strict mode, utf8mb4 и фактическими ограничениями длины/индексов.
6. Поддержка PHP CLI, cron и агентов для очистки.
7. Права доступа, CSRF и штатные механизмы административной панели.
8. Требования и правила публикации модуля в Marketplace.

## 4. Политика заявлений о совместимости

Не указывать в README и карточке продукта версии, которые не проверены на тестовой матрице. Требования платформы и фактически протестированная совместимость самого модуля должны быть представлены раздельно.
