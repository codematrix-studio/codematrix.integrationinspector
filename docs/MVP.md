# Спецификация MVP

- **Версия:** 0.1 (черновик)
- **Дата:** 2026-11-24
- **Статус:** на согласовании; не является окончательным техническим заданием.

## 1. Цель MVP

Дать разработчику возможность явно зарегистрировать начало операции интеграции, завершить её успехом или ошибкой и изучить сохранённое событие в административной панели.

## 2. Обязательные возможности

1. Регистрация источников интеграции.
2. Регистрация входящих и исходящих событий.
3. Уникальный идентификатор события.
4. Correlation ID для связи нескольких событий.
5. Фиксация типа операции и произвольных безопасных метаданных.
6. Фиксация результата, HTTP-статуса и длительности, если они применимы.
7. Фиксация исключения без нарушения исходного потока обработки.
8. Просмотр списка событий и карточки события.
9. Фильтрация по периоду, источнику, направлению и статусу.
10. Маскирование секретов до сохранения.
11. Ограничение размера тела запроса/ответа.
12. Настраиваемое отключение сохранения тел.
13. Очистка записей старше заданного срока.
14. Проверка прав доступа к административным данным.

## 3. Состояния события

- `pending` — событие начато, результат ещё не зафиксирован;
- `success` — операция завершилась успешно;
- `error` — операция завершилась ошибкой;
- `abandoned` — событие признано незавершённым по результатам обслуживания/очистки, если такой механизм будет утверждён.

Не считать отсутствие финализации доказательством ошибки до определения правил обработки зависших событий.

## 4. Предварительный API

Иллюстрация интерфейса, не утверждённый контракт:

```php
$event = Inspector::start('1c', 'order.export', [
    'direction' => 'outgoing',
]);

try {
    // Выполнение интеграции.

    Inspector::success($event, [
        'http_status' => 200,
    ]);
} catch (\\Throwable $exception) {
    Inspector::failure($event, $exception);
    throw $exception;
}
```

До реализации необходимо утвердить:
- тип и жизненный цикл объекта события;
- поведение при недоступности хранилища;
- транзакционность;
- формат тел и заголовков;
- интерфейс добавления контекста;
- политику ошибок самого Inspector.

## 5. Административные разделы

- Обзор (минимальный или отложенный — уточнить).
- Журнал событий.
- Источники интеграций.
- Настройки хранения и безопасности.

Карточка события:
- общая информация;
- запрос;
- ответ;
- ошибка и технический контекст.

## 6. Безопасность

Обязательные требования:
- маскирование Authorization, Cookie, токенов, паролей и иных заданных ключей;
- возможность исключать поля и заголовки по настройкам;
- маскирование до записи в постоянное хранилище;
- лимит размера полезной нагрузки;
- отключение записи тела целиком;
- контроль доступа по группам/правам Битрикс;
- защита административных операций штатными средствами платформы;
- не записывать платёжные секреты и чувствительные персональные данные без отдельного обоснования и явной настройки.

Маскирование по именам полей не гарантирует обнаружение секретов внутри произвольного текста. Это ограничение должно быть отражено в документации.

## 7. Что не входит в MVP

- повторное выполнение запросов;
- автоматическое исправление ошибок;
- конструктор интеграций;
- готовые коннекторы ко всем внешним системам;
- облачный сервис;
- сложные уведомления;
- расширенная аналитика.

## 8. Нефункциональные требования

- диагностический модуль не должен выбрасывать собственные исключения в основной поток интеграции, если выбран безопасный режим;
- измерение длительности должно быть монотонным;
- хранение должно быть индексировано по основным фильтрам;
- объём данных должен быть ограничен настройками;
- должна быть предусмотрена очистка;
- операции записи должны иметь понятное поведение при отказе БД.

## 9. Критерии готовности MVP

- модуль устанавливается и удаляется штатным способом;
- API покрыт тестами;
- события корректно проходят жизненный цикл;
- ошибки интеграции фиксируются и не теряются;
- ошибки самого логгера не ломают интеграцию в безопасном режиме;
- секреты маскируются до сохранения;
- список и карточка событий работают с правами доступа;
- очистка не удаляет записи за пределами заданной политики;
- проверена работа на заявленной матрице PHP/Битрикс/БД.
