Обновляется по мере выполнения задач. Статусы отражают фактическое состояние, а не намерения.

| Этап | Результат | Статус |
|---|---|---|
| 0. Концепция | Назначение, аудитории, границы продукта и стратегическая роль | Выполнено предварительно |
| 1. Спецификация MVP | Функции, безопасность, критерии готовности | Черновик уточнён |
| 2. Архитектура | API, подсистемы, схема данных | Проект API подготовлен; схема данных не завершена |

| 9. Публичный релиз | Лицензия, документация, упаковка, примеры, публикация | Не начато |

## Принципы развития

- Продукт распространяется бесплатно; платные редакции и подписки не планируются.
- Качество и полезность для сообщества важнее скорости выпуска.
- Репозиторий должен демонстрировать инженерную культуру: понятная архитектура, тесты, документация, история решений и релизов.
- До публичного релиза необходимо выбрать лицензию и добавить полный текст LICENSE.
- Не заявлять поддержку платформ и окружений, на которых модуль не проверен.

## Правило перехода между этапами

Этап не отмечается выполненным только потому, что он описан. Нужны проверяемые результаты: код, тесты, решение или подтверждённая проверка.

## Ближайшие задачи

1. Согласовать или скорректировать проект публичного API из [API.md](API.md).
2. Уточнить открытые вопросы API: формат ID, результат begin(), регистрацию источников и пользовательский Sanitizer.
3. Проверить минимальную версию ядра Битрикс, ORM, установщик, права, cron/agents и требования распространения.
4. Спроектировать физическую схему хранения с индексами и политикой роста данных.
5. Выбрать лицензию исходного кода до первого публичного релиза.
6. После утверждения контрактов подготовить тестовые сценарии и только затем переходить к реализации.
