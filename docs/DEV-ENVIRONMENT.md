# Среда разработки и тестирования

- **Версия:** 0.1
- **Дата:** 2026-11-24
- **Статус:** проект решения; конфигурация Composer/PHPUnit ещё не добавлена и тесты не запускались.

## 1. Принципы

- У модуля не должно быть обязательных runtime-зависимостей от Composer-пакетов.
- Разработческие инструменты и тестовые зависимости не должны попадать в поставку модуля на сайт.
- Публичный API и внутренние классы должны загружаться штатным механизмом Bitrix.
- Unit-тесты должны запускаться без установленного Bitrix там, где тестируемый класс не зависит от ядра.
- Интеграционные тесты должны запускаться на отдельном тестовом сайте с реальным ядром и MySQL.
- Ни одна версия PHP/ядра/СУБД не считается поддерживаемой без успешного прогона соответствующего набора.

## 2. PHP и PHPUnit

Предлагаемая базовая среда:
- PHP CLI 8.2+;
- Composer 2.x только для разработки;
- PHPUnit 11.5.x как dev dependency: эта ветка совместима с PHP 8.2; PHPUnit 12 требует PHP 8.3 и не подходит для нижней границы проекта;
- расширения PHP для PHPUnit: DOM/XML, mbstring, JSON; дополнительные расширения включать только по необходимости тестов.

PHPUnit не устанавливается на рабочие сайты и не включается в архив модуля.

Официальная документация PHPUnit:
- [Установка PHPUnit 12.5 и требования к PHP](https://docs.phpunit.de/en/12.5/installation.html) — PHPUnit 12 требует PHP 8.3; руководство описывает Composer как dev dependency.
- [Руководство PHPUnit 11.5](https://docs.phpunit.de/en/11.5/).

## 3. Разделение наборов тестов

| Набор | Путь | Требования |
|---|---|---|
| Unit | `tests/Unit` | PHP CLI и PHPUnit; без Bitrix и БД |
| Integration | `tests/Integration` | отдельный тестовый сайт Bitrix, PHP CLI, MySQL |
| Security | `tests/Security` | тестовый Bitrix, тестовые роли и данные |
| Compatibility | `tests/Compatibility` | отдельные окружения для каждой заявляемой версии |
| Manual | документация тестов | тестовый сайт и браузер |

Интеграционные тесты не должны обращаться к рабочим сайтам или реальным внешним интеграциям.

## 4. Загрузка классов

Для production-загрузки использовать штатный механизм Bitrix Loader и регистрацию namespace модуля в `include.php`. Composer autoload допускается только в dev/test окружении.

Предлагаемый корневой namespace:
- `CodeMatrix\IntegrationInspector\Api` — публичный контракт;
- `CodeMatrix\IntegrationInspector\Event` — жизненный цикл;
- `CodeMatrix\IntegrationInspector\Storage` — внутреннее хранилище;
- `CodeMatrix\IntegrationInspector\Sanitizer` — обработка данных.

Внутренние классы не должны становиться публичным API по факту доступности в namespace.

## 5. Предлагаемая структура тестов

```text
tests/
├── Unit/
│   ├── Api/
│   ├── Event/
│   ├── Sanitizer/
│   └── Support/
├── Integration/
│   ├── Storage/
│   ├── Transaction/
│   ├── Installation/
│   └── Cleanup/
├── Security/
└── bootstrap/
    ├── unit.php
    └── integration.php
```

Integration bootstrap получает путь к тестовому корню Bitrix из переменной окружения. Не хранить в репозитории пароли и конфигурацию реального сайта.

## 6. Критерии готовности среды

- [ ] PHP CLI 8.2+ доступен.
- [ ] Composer 2.x доступен.
- [ ] PHPUnit 11.5.x устанавливается как dev dependency.
- [ ] Unit suite запускается без Bitrix.
- [ ] Integration suite корректно пропускается/останавливается с понятным сообщением, если тестовый Bitrix не настроен.
- [ ] Конфигурация тестового сайта и реквизиты БД не попадают в Git.
- [ ] В релизный архив не попадают `vendor/`, PHPUnit и тестовые конфигурации.
- [ ] Есть воспроизводимая инструкция подготовки тестового окружения.

## 7. Следующий шаг

После подтверждения технических spike добавить `composer.json`, `phpunit.xml.dist`, bootstrap и первый набор unit-тестов для чистых PHP-классов. Не добавлять фиктивные тесты только ради зелёного статуса CI.
