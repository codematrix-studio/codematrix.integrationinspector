# Пакеты обновлений Bitrix

## 0.1.1

Исходники обновления находятся в `updates/0.1.1/`. Готовый пакет собирается скриптом:

```bash
bash scripts/build-update.sh 0.1.1
```

Результат: `dist/0.1.1.zip`. Скрипт собирает содержимое `local/modules/codematrix.integrationinspector/` в корень пакета, добавляет корневые `updater.php` и `description.ru`, проверяет совпадение версии и обязательные файлы, затем проверяет целостность ZIP и его структуру.

GitHub Actions выполняет эту сборку при push, pull request и ручном запуске workflow. Архив доступен как artifact сборки на 14 дней; публикация GitHub Release или размещение на сервере обновлений автоматически не выполняется.

### Порядок работы updater

Bitrix запускает корневой `updater.php` до автоматического копирования остальных файлов обновления. Поэтому скрипт сначала явно копирует `lib/Storage/` через штатный `$updater->CopyFiles()`, затем загружает `MigrationRunner` из `/local/modules/`. После успешного выполнения мигратора Bitrix продолжает стандартное копирование остальных файлов пакета.

Скрипт сначала проверяет, установлен ли модуль: Bitrix запускает updater для всех модулей из лицензии, в том числе неустановленных. Для неустановленного модуля скрипт завершается без копирования файлов и без обращения к БД. При ошибке он задаёт `$errorMessage`, который штатный механизм Bitrix использует для отказа в установке обновления, и пишет техническую причину в PHP error log. Скрипт не предполагает наличие нового API в установленной версии модуля и не выполняет миграции на пользовательском хите. В случае несовпадения существующей схемы обновление завершается ошибкой; таблицы и данные автоматически не пересоздаются.

**Важно:** CI проверяет сборку и структуру архива, но не заменяет установку и обновление на целевой BitrixVM. Перед публикацией обновления необходимо отдельно проверить полный цикл на стенде с поддерживаемой версией Bitrix и резервной копией БД.
